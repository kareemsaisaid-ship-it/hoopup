## รูปแบบที่แนะนำ: เล่าเรื่อง 1 เคส แล้วโชว์ต้นแบบ 4–5 นาที

ใช้ต้นแบบมือถือของเพื่อนเป็นภาพหลัก ถ้ามีเครื่องที่เปิดได้และซ้อม flow แล้ว; เตรียม [ภาพหน้าจอ v1](mvp_tasks_2026-10-28/reference/hoopup-v1.png) เป็นสำรอง ส่วน SQL/backend ที่เตรียมไว้นำมาอธิบายแนวทางพัฒนาอีกชิ้นหนึ่ง ยังไม่เรียกสองชิ้นนี้ว่าระบบที่เชื่อมสมบูรณ์แล้ว

ไฟล์แนบที่ตรวจเป็น Expo/React Native prototype; รอบนี้ตรวจ source ไม่ได้ติดตั้ง dependencies หรือรันแอปเพื่อน จึงยังไม่ยืนยันว่าเปิดบนอุปกรณ์ใดได้สำเร็จ

เพิ่มขอบเขตหนึ่งประโยค:

> “หนึ่งห้องแทนหนึ่งทีมที่จะไปเล่น ส่วนการใช้สนามสาธารณะยังเป็นไปตามกติกาหน้างานครับ”

### 0:40–2:40 — โชว์ flow ที่มีใน source

1. **หน้าแรก:** เปิดห้องตัวอย่างสนามสวนลุม แสดงว่ามี 3/5 คนและขาดอีก 2 คน เลือกดู 3x3/5x5 และระดับการเล่น
2. **คนหาทีม:** เปิดห้อง `r1` ซึ่งเข้าได้เลย → กดเข้าทีม → จำนวนควรเป็น 4/5 → ส่งข้อความนัดพบในห้อง → ถอนตัวกลับเป็น 3/5
3. **ฝั่งผู้จัด:** สร้างห้อง 5x5 ขาด 2 คน → เลือกสนามและเวลา → ประกาศ → เห็นห้องของตนพร้อมสมาชิกสมมติ 3/5
4. **โปรไฟล์:** ชี้ให้เห็นตำแหน่งและระดับที่ช่วยตัดสินใจเข้าทีม การแจ้งเตือน/สนามประจำที่แสดงยังเป็น UI ต้นแบบ

เส้นทางนี้อ้างจาก source เท่านั้น ต้องซ้อมบนเครื่องเพื่อนก่อนเริ่มคุย หากยังไม่เคยรันสำเร็จ ใช้ภาพประกอบเล่า flow แทนการรับประกัน live demo

วันนี้เสนอใช้ “เข้าได้เลย” ใน demo หลัก เพราะ source มีการส่งคำขอ pending แต่ยังไม่พบคำสั่ง/หน้าจอผู้จัดอนุมัติให้จบ flow ไม่ควรค้างการสาธิตไว้ที่รออนุมัติ

## แนวตอบคำถามที่อาจถูกถาม

**ต่างจาก LINE/Facebook อย่างไร?**

> “เราจัดข้อมูลสนาม เวลา จำนวนที่ขาดและสถานะเข้าร่วมเป็นโครงสร้างเดียวกันครับ คนหาทีมจึงเห็นเงื่อนไขก่อนกดร่วม ส่วนความสะดวกหรือเวลาที่ลดได้ยังต้องทดลองเทียบวิธีเดิมกับผู้ใช้จริงครับ”

**ส่วนที่เป็นงานวิศวกรรมอยู่ตรงไหน?**

> “ส่วนที่วางแผนพิสูจน์คือการคุมจำนวนคนเมื่อเข้าพร้อมกัน ความถูกต้องของสิทธิ์สมาชิก การค้นสนามตามพิกัด และการรักษาสถานะห้องกับการแจ้งเตือนให้ตรงกันครับ ส่วนที่ต้นแบบทำอยู่ยังไม่ถือว่าพิสูจน์ทั้งหมดแล้ว”

**จะวัดผลอย่างไร? — ข้อเสนอให้อาจารย์ช่วยพิจารณา**

- เชิงระบบ: จำนวนไม่เกินความจุเมื่อเข้า/อนุมัติพร้อมกัน, คำสั่งซ้ำไม่เพิ่มคนหรือข้อความซ้ำ, ผู้ไม่มีสิทธิ์อ่านแชทไม่ได้, ผลค้นสนามตามรัศมีตรงกับชุดข้อมูลทดสอบ
- เชิงใช้งาน: สัดส่วนผู้ทดลองที่สร้าง/หา/เข้าร่วมนัดสำเร็จ, เวลาที่ใช้ทำภารกิจ และจุดที่กดผิดหรือไม่เข้าใจ
- เชิงสนามจริง: แยก “กดร่วมในแอป” จาก “ไปพบกันจริง” วัดการเติมทีมและการนัดพบในพื้นที่นำร่องตามแผนที่อาจารย์เห็นชอบ ยังไม่มีผลทดลองภาคสนามในเอกสารนี้

**ถ้าคนน้อย แอปจะมีประโยชน์หรือไม่?**

> “การหาคนต้องมีผู้เข้าร่วมในพื้นที่ครับ เราเสนอเริ่มกับสนามและผู้จัดกลุ่มเล็กที่เข้าถึงได้ก่อน เพื่อทดลองว่ามีการสร้างนัด เข้าร่วม และไปพบกันจริงหรือไม่ ยังไม่อ้างว่ามีชุมชนผู้ใช้พร้อมแล้วครับ”

## สิ่งที่ต้องเตรียมก่อนเข้าพบ

- เปิดแอปและซ้อมเส้นทางสาธิตข้างต้นให้จบหนึ่งรอบ ใช้ข้อมูลเดิมที่รู้ผลและเตรียมภาพหรือคลิปสำรอง
- หากใช้เพียงภาพ v1 ให้ระบุว่าเป็นภาพแบบหน้าจอ ไม่เรียกว่า screenshot ของระบบที่เชื่อม backend แล้ว
- อธิบายแต่ละส่วนว่า “ทำแล้ว”, “ทดลองด้วยข้อมูลจำลอง”, หรือ “วางแผนทำ” ให้สม่ำเสมอ โดยเฉพาะ GPS/จำนวนคนที่สนาม/แจ้งเตือน
- จดข้อสรุปอาจารย์เรื่องแกน ขอบเขต สิ่งที่ต้องพิสูจน์ และเกณฑ์ประเมิน เพื่อปรับแผนเดียวร่วมกันหลังประชุม
